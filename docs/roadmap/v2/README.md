## 1. The operational flow (what must work end to end)

This is the flow the docs promised ([`../../PS/solution.md`](../../PS/solution.md), [`../github-app.md`](../github-app.md) §5, [`../dashboard.md`](../dashboard.md)). Every v2 phase makes one more step of it real.

```
 1 Sign in        landing ─► "Sign in with GitHub" (Auth.js, the GitHub App's own OAuth) ─► /app
 2 Install        no installation? ─► /onboarding ─► github.com/apps/<slug>/installations/new
                  ─► GitHub redirects to /onboarding?installation_id=… ─► repos listed
 3 Map the code   install webhook ─► scan (ts-morph) ─► code map ─► /app/graph (APIs → calls → fields → code → workflows)
 4 Setup PR       one-time PR adds withAliases() wrappers + seismo/aliases.json (a human merges it)
 5 Watch traffic  Settings ─► create SDK key ─► app env SEISMO_KEY ─► fingerprints ─► /app/status live
 6 Detect         provider changes ─► detectors ─► drift event ─► SSE ─► timeline, bell, red graph path
                  ─► alerts: WhatsApp (breaking), GitHub issue, Slack/Discord/email if set
 7 Fix safely    rename ─► alias rule PR (only seismo/aliases.json) ─► checks C1–C8 ─► human merges ─► resolved
                  money / branching / persistence / units ─► review queue ─► human decides (expected / snooze / suggestion PR)
 8 Look ahead     radar: changelogs, OpenAPI diffs and Sunset headers matched to the code before the change lands
```

Data path inside the dashboard (decided in v2-P0):
```
browser ── fetch /api/seismo/v1/... ──► Next route handler (server) ── Bearer JWT(sub=login, AUTH_SECRET) ──► backend :4000
browser ── EventSource /api/seismo/v1/events ──► same handler streams the backend SSE (no token in the URL)
```
- The GitHub access token and `AUTH_SECRET` never reach the browser.
- `NEXT_PUBLIC_USE_MOCKS=1` keeps Adarsh's mock data for design work.
